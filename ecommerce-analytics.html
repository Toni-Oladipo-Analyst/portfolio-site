01 The Problem

An ecommerce business had 1,200 customers worth of raw, uncleaned transactional and behavioral data sitting in CSV files with 25 fields covering demographics, purchasing history, engagement metrics, and satisfaction scores.

Management needed answers to critical questions: Who are our most valuable customers? Why are customers leaving? Which regions and segments drive the most profit? Where should we invest to grow?

There was no analytics infrastructure in place — no database, no dashboards, no reporting. Everything had to be built from scratch.

02 My Process

Phase 1

Data Cleaning & Preparation (Excel)

Started with the raw CSV export containing inconsistencies, duplicates, and missing values across 25 columns. Cleaned and standardized everything in Excel before importing into MySQL — fixed formatting issues, handled null values, removed duplicate records, and ensured consistent data types.

Phase 2

Database Design & Implementation (MySQL)

Designed a normalized relational schema with two core tables linked by a foreign key with cascading updates and deletes. Added constraints for data integrity (satisfaction scores between 1-5, churn as binary flag).

SQL — Schema Design 
CREATE TABLE customers (
    customer_id              INT PRIMARY KEY,
    age                      TINYINT NOT NULL,
    gender                   VARCHAR(20) NOT NULL,
    country                  VARCHAR(50) NOT NULL,
    region                   VARCHAR(50) NOT NULL,
    income_bracket           VARCHAR(20),
    loyalty_tier             VARCHAR(20),
    referral_source          VARCHAR(30)
    -- ... 14 columns total
);

CREATE TABLE customer_activity (
    customer_id               INT PRIMARY KEY,
    total_spent_usd           DECIMAL(10,2) NOT NULL DEFAULT 0.00,
    total_orders              INT NOT NULL DEFAULT 0,
    days_since_last_purchase  INT NOT NULL,
    satisfaction_score        TINYINT,
    churn                     TINYINT(1) NOT NULL DEFAULT 0,

    CONSTRAINT fk_customer
        FOREIGN KEY (customer_id)
        REFERENCES customers(customer_id)
        ON DELETE CASCADE ON UPDATE CASCADE,

    CONSTRAINT chk_satisfaction
        CHECK (satisfaction_score BETWEEN 1 AND 5)
);
Phase 3

Customer & Revenue Analysis

Wrote queries to break down revenue by geography, loyalty tier, payment method, device type, and referral source. Identified which segments drive the most value and where the business is underperforming.

SQL — Revenue by Geography 
SELECT c.region, c.country,
       COUNT(*) AS customer_count,
       SUM(a.total_spent_usd) AS total_revenue,
       ROUND(AVG(a.total_spent_usd), 2) AS avg_spend_per_customer,
       ROUND(SUM(a.total_spent_usd) * 100.0
           / (SELECT SUM(total_spent_usd) FROM customer_activity), 2)
           AS pct_of_total_revenue
FROM customers c
JOIN customer_activity a ON c.customer_id = a.customer_id
GROUP BY c.region, c.country
ORDER BY total_revenue DESC;
Phase 4

Customer Retention & Churn Analysis

Defined churn as no purchase in 365+ days and validated this rule against the dataset's own churn flag (0 disagreements). Segmented customers into risk buckets by recency, then cross-referenced with loyalty tier and satisfaction scores to identify who to target for retention campaigns.

SQL — Churn Risk Segmentation 
SELECT
  CASE
    WHEN a.days_since_last_purchase <= 90  THEN '0-90 days (Active)'
    WHEN a.days_since_last_purchase <= 180 THEN '91-180 days (Watch)'
    WHEN a.days_since_last_purchase <= 365 THEN '181-365 days (At Risk)'
    ELSE '365+ days (Churned)'
  END AS recency_bucket,
  COUNT(*) AS customer_count,
  ROUND(AVG(a.total_spent_usd), 2) AS avg_spend
FROM customer_activity a
GROUP BY recency_bucket
ORDER BY MIN(a.days_since_last_purchase);

-- Retention targets: at-risk, low satisfaction, high spend
SELECT c.customer_id, c.country, c.loyalty_tier,
       a.total_spent_usd, a.satisfaction_score
FROM customers c
JOIN customer_activity a ON c.customer_id = a.customer_id
WHERE a.days_since_last_purchase BETWEEN 91 AND 365
  AND a.satisfaction_score <= 3
ORDER BY a.total_spent_usd DESC
LIMIT 20;
Phase 5

Advanced Analytics — Window Functions

Used RANK, PERCENT_RANK, and cumulative SUM window functions to identify revenue concentration (top 10% of customers = 50.6% of revenue), rank customers within each region, and find local market leaders by country.

SQL — Revenue Concentration Analysis 
SELECT customer_id,
       total_spent_usd,
       RANK() OVER (ORDER BY total_spent_usd DESC) AS revenue_rank,
       ROUND(total_spent_usd * 100.0
           / SUM(total_spent_usd) OVER (), 3)
           AS pct_of_total_revenue
FROM customer_activity
ORDER BY revenue_rank
LIMIT 20;

-- Top 3 customers within each region
SELECT * FROM (
    SELECT c.region, c.customer_id, a.total_spent_usd,
           RANK() OVER (PARTITION BY c.region
                        ORDER BY a.total_spent_usd DESC)
               AS rank_in_region
    FROM customers c
    JOIN customer_activity a ON c.customer_id = a.customer_id
) ranked
WHERE rank_in_region <= 3
ORDER BY region, rank_in_region;
Phase 6

Reporting Views

Created 6 reusable SQL views to serve as data sources for the Power BI dashboard, so the analysis refreshes automatically without rewriting queries:

  • vw_customer_churn_risk — Segments every customer into Active, Watch, At Risk, or Churned
  • vw_revenue_by_geography — Revenue, customer count, and % contribution by region and country
  • vw_loyalty_performance — Spend, orders, satisfaction, and churn rate by loyalty tier
  • vw_customer_segments — Full customer profile with derived age bands, spend segments, and lifecycle stages
  • vw_executive_kpis — Single-row summary of all key metrics for the dashboard header
  • vw_signup_cohorts — Monthly cohort analysis tracking revenue and churn over time
Phase 7

Stored Procedures

Built 3 parameterized stored procedures for on-demand filtered reporting — by country, spend threshold, and loyalty tier — so stakeholders can pull specific reports without writing SQL.

Phase 8-10

Power BI Dashboard & Live Refresh

Connected Power BI directly to the 6 MySQL views as live data sources. Built an executive dashboard with KPI cards (Churn Rate, Total Revenue, Revenue At Risk, Average Satisfaction, Total Customers), churn trends by loyalty tier, revenue by country, acquisition by referral source, spend segment mix, and interactive slicers for Region, Loyalty Tier, and Spend Segment.

Demonstrated live data refresh by inserting, updating, and deleting a test customer (ID 1201) through SQL, with the dashboard reflecting changes in real time via the underlying views.
